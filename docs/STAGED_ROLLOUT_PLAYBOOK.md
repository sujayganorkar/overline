# 1 Million User Staged Rollout Playbook & Operations Guide

This playbook outlines the deployment lifecycle, operational monitoring, and emergency response procedures for scaling PdfCraft Mobile to 1,000,000+ active users.

---

## 1. Google Play Staged Rollout Schedule

Never release a major version directly to 100% of production. Follow this phased progression:

```
[Internal Track] 
       │ (100% pass, 0 blocker regressions)
       ▼
[Closed Alpha] ────▶ 1,000 power users (24-48 hours)
       │
       ▼
[Open Beta Track] ──▶ 10,000 opt-in users (48-72 hours)
       │
       ▼
[Production Staged Rollout]:
       ├── Day 1:  1% of user base (~10,000 users)
       ├── Day 2:  5% of user base (~50,000 users)
       ├── Day 3: 20% of user base (~200,000 users)
       ├── Day 4: 50% of user base (~500,000 users)
       └── Day 5: 100% full release (~1,000,000 users)
```

## 2. Google Play Android Vitals & SLO Thresholds

Monitor the Google Play Console **Android Vitals** dashboard continuously during each rollout stage.

| Metric | Target (SLO) | Google Play "Bad Behavior" Threshold | Action If Exceeded |
| :--- | :--- | :--- | :--- |
| **Crash Rate** | < 0.2% | **1.09%** (Core Vitals limit) | **Halt rollout immediately** |
| **ANR Rate** (Application Not Responding) | < 0.1% | **0.47%** (Core Vitals limit) | **Halt rollout immediately** |
| **App Startup Time (Cold)** | < 1,200 ms | > 5,000 ms | Review plugin initialization |
| **App Startup Time (Warm)** | < 600 ms | > 2,000 ms | Profile engine reactivation |
| **Slow Rendering Frames (>16ms)** | < 2% | > 8% | Review LRU cache size & DPI |

> **Note on Google Play Bad Behavior Thresholds**: Exceeding the bad behavior thresholds reduces search visibility across Google Play store rankings. Staged rollouts protect app ranking by catching regressions when only a tiny fraction of users is affected.

## 3. Remote Feature Flag & Kill-Switch Activation

If a specific tool (e.g., OCR, Image Conversion, or target compression) triggers crashes or high memory consumption on specific OEM devices, **do not wait for an app store update** (which takes 24–72 hours to review). 

Use `FeatureFlagService` via remote config:

### Kill-Switch JSON Payload Format:
```json
{
  "flags": {
    "tool_doc_ocr_enabled": false,
    "tool_image_to_pdf_enabled": true
  },
  "disabled_notices": {
    "doc_ocr": "OCR is temporarily disabled for maintenance. An update will restore it shortly."
  }
}
```

When disabled:
1. The app gracefully intercepts tool launches in `_launchTask`.
2. Users see the friendly maintenance notice.
3. No native panic or uncaught exception occurs.
4. Telemetry sink records the prevented crash.

## 4. Crash De-obfuscation & Symbolication

Every build generated by `tools/build-bundle.sh` stores:
- `dist/bundle/mapping.txt` (R8 ProGuard obfuscation map)
- `dist/bundle/native-debug-symbols.zip` (NDK native symbols for `libpdfcraft_mobile_api.so`)

### Uploading to Google Play Console:
1. Go to **Release** > **App bundle explorer**.
2. Select the version code.
3. Navigate to **Downloads** > **Native debug symbols**.
4. Upload `native-debug-symbols.zip`.
5. Navigate to **Reobfuscation / Mapping**.
6. Upload `mapping.txt`.

This ensures all Java, Kotlin, Dart, and Rust stack traces appear with file names and line numbers in Google Play Console and crash telemetry sinks.
